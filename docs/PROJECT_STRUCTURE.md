# 工程结构与命名规范

[返回首页](../README.md) · [工程总览](PROJECTS.md) · [快速开始](QUICKSTART.md)

## 统一的是导航，保留的是可运行路径

每个视频有一个稳定目录与工程 ID。显示标题、系列、集数和当前版本写在元数据中；不为了换标题而重命名物理目录。旧工程已经使用的 `src/`、`public/`、`scripts/`、`v1/`、`v3/`、`delivery/` 等目录继续保留，统一导航负责说明它们对应什么。

本次仓库整理不包含 `ai_evolution_*` / `ai_revolution*` 系列及其 `publication_2026-09-23` 发布包，也不把本机历史对话、API 凭据或工具运行会话作为视频源码。

## 每个工程的入口

| 文件 / 位置 | 内容 |
|---|---|
| `README.md` | 主题、当前入口、环境、素材缺口、检查与渲染方法 |
| `project.json` | 可供工具读取的工程信息；具体字段以仓库生成的实际文件为准 |
| `assets.manifest.json` | 已包含、可从 Release 恢复、仍需本地备份的素材清单 |
| 原有引擎目录 | 继续承载真正可编辑的源码与构建脚本 |
| 来源台账 | 论文、图片、模型、音乐、字体的来源、许可与哈希 |
| 版本记录 | 已完成的版本、实际检查范围、限制与回退入口 |

已有 `project.json` 的字段不应被盲目覆盖。工作台自己的 `.studio/` 运行数据与可共享的工程导航是不同内容；个人会话、日志、学习输入和绝对路径记录无需随源码同步。

## 新项目推荐目录

```text
video_project/<stable-id>/
├─ README.md
├─ project.json
├─ source/                  场景、镜头表、算法、构建脚本
├─ assets/                  图片、模型、贴图及其来源清单
├─ audio/
│  ├─ narration/            源句与选定旁白
│  ├─ bgm/                  可用配乐与许可
│  └─ master/               最终混音
├─ subtitles/               原文、SRT / VTT 与对齐记录
├─ covers/
│  ├─ v001/                各画幅封面与可编辑版式
│  └─ copy/                平台发布文案
├─ references/              论文、事实、参考片与使用依据
├─ output/v001/             已核验交付及清单
└─ work/v001/               可重建缓存、抽帧与短样片
```

若框架要求 `src/` 与 `public/`，直接保留这些目录并在导航中映射；无需同时制造一套重复源码。引用素材只保留一份稳定路径，避免每期复制整套依赖或音乐库。

## 命名

- 新 ID 使用简短的 `lower_snake_case`。历史中文目录保留，中文显示名写入导航。
- 新版本使用 `v001`、`v002`，不用“最终版2”“真正最终版”。旧 `v3` 等目录不批量改名。
- 文件明确写出主题、版本与用途，例如 `密码学_v003_1080p.mp4`、`密码学_v003_16x9.jpg`。
- 画幅固定使用 `16x9`、`3x4`、`4x3`、`9x16`、`1x1`。不同画幅分别设计主体和文字位置。
- “最新”表示索引中的当前选择；“已验收”必须有明确的检查记录，二者不混用。

## 版本与清理

保存当前可用版本的源码、锁文件、源句、字幕、混音、模型、许可及重建脚本，并保留可回退入口。可重建缓存不进入 Git；删除本地中间文件前先证明它们未被当前版本引用。

符号链接与 Windows 目录联接不等于独立副本。整理程序不得递归进入并删除链接目标，也不能把本机 `node_modules` 联接当成新机器可用的依赖安装。大型媒体另行管理，见 [素材指引](ASSETS.md)。
