## 新增运动状态检查

`node v3/scripts/qa_motion_state_v3.mjs` 会在不启动Chrome/WebGL的情况下实例化真实 `Stations.ts`，用无操作Canvas支持构造文字纹理，逐站点覆盖站点前后各3秒、按30fps运行 `Station.update`，比较每个对象的世界变换，并将中心点投影到真实相机。结果写入 `research/motion-state-qa.json`。

本检查的确定性寻帧部分通过：同一组件先更新到其他时间再回到原时间，状态哈希一致；全局导引金色粒子每帧位移最大约0.163世界单位。

但检查也发现真实、可复现的运动跳变，不能以“确定性”掩盖：

| 站点 | 最大单帧世界位移 | 主要原因 |
|---|---:|---|
| hook / return | 约3.395 | Hero 数据方块使用取模循环 |
| encode | 约6.479 | `carriers` 使用取模路径，`beam` 也有周期跳转 |
| constraints | 约0.807 | 拒绝片段在站内边界移动较急 |
| fountain | 约8.350 | `runners` 使用 `% 1`，从路径终点回到起点 |
| wetlab | 约1.752 | 液滴与片段使用周期回绕 |
| consensus | 约0.079 | 连续运动状态，未发现投影跳变 |
| model | 约0.188 | 轨道粒子取模循环，当前阈值未触发主要投影跳变 |

Fountain 的一个可见投影跳变已复现：约81.167秒，`runners[5]` 从本地 `x≈3.895,y≈−0.968` 瞬移到 `x≈−3.898,y≈2.030`，单帧约8.35单位；轨迹端点从画面内进入下一帧仍在画面内。Encode carriers也有约5–6单位的端点跳变。完整对象与帧列表见 `motion-state-qa.json`。

这不是相机轨迹问题，而是对象路径本身的回绕问题。要满足连续电影镜头，应把取模循环改为有限往返、留在镜头外重置，或使用相邻周期的连续展开。该复核任务遵守范围，仅新增脚本和研究记录，没有修改 `src`。

### 修复后复核

主代理随后将上述可见循环改为连续往返相位，并重新运行同一脚本。当前 `motion-state-qa.json` 状态为 `PASS`：所有站点的 `projectedJumpObjectCount` 均为0，确定性寻帧仍通过；最大单帧世界位移为 Fountain 约0.491、Wetlab约0.462、Constraints约0.367，均为连续运动而非端点瞬移。Hook、Encode、Return的最大位移分别约0.029、0.048、0.029世界单位。该结果仍只证明CPU对象状态与中心点投影，最终GLB、shader和字幕遮挡需用渲染帧/片段复核。

## “通过”不代表的事情

自动检查没有证明：

- 文字、模型、论文卡片在每一帧都没有遮挡；
- 旁白的故事性、发音和音乐的主观听感；
- 3D/GLB替换资产的实际尺寸、材质和视觉品质；
- shader粒子在ANGLE下的最终观感；
- 站间传递的“同一数据颗粒”在语义上真实连续。

最终验收需要先修复或明确处理上述回绕跳变，再以当前代表帧和每个边界前后连续片段复看，最后渲染MP4并使用 `qa_timeline.mjs --video=<实际路径>` 运行 ffprobe 验收。交付文件不存在前，脚本保持 `releaseApproved:false`。
