# AI Engineer 发布片 · 可录音叙事 v2

时长105秒，沿用8个镜头窗口。实际合成计划以 `launch-v2-voice-plan.json` 为准；本稿未覆盖旧成片。

主线：**需求 → 任务图 → 专家工具 → 失败反馈 → 复查留档**。

## 旁白与镜头

### 000.0–007.0s · AI ENGINEER

从一句需求，到一套工程方案，中间要跨过多少工具？

画面：黎明海面上一台比例可信的浮式风机。镜头先贴着浪尖掠过，再下降到浮体与系泊的交界；风推叶片、浪托平台、缆绳回拉用细小但真实的运动表现。不要用过度科幻的白球或过薄的玩具浮体。

运镜：24mm 低空掠海 → 沿浮体边缘下潜 → 环绕系泊节点 → 在塔底高光上锁定，下一镜的网页光标从同一高光位置长出来。

衔接：塔底高光拉成一条细线，线条变成网页输入框的光标；海面纹理继续作为 UI 背景的细线，不切黑。

### 007.0–019.0s · 从一句话，变成一张任务图

AI Engineer，把这条路接起来。工程师说明目标和约束，系统把需求拆成任务图，再交给专家工具。

画面：真实本地AI Engineer工作区录屏：输入工程需求但不提交。目标与约束以动效文字提炼；只将任务图作为架构示意，不伪装成录屏新执行的结果。

运镜：从海面共享反光进入网页输入框，追踪已录制光标；文字沿纸面透视排布，镜头压低后转入设计域。

衔接：输入框边缘延伸为图纸和设计域边界；不穿入Run按钮，不虚构启动求解。

### 019.0–034.0s · 让材料，沿着力留下

几何工具建模，网格工具划分单元，贝索根据受力，一轮轮调整材料。材料往哪里留，构件多粗多厚，分别交给对应的算法求解。

画面：三维设计域由网页网格接续而来。单元像薄片一样被力线牵引，低贡献区域逐层撤去，主受力路径保留；44 个状态沿一条弯曲时间带展开，最终骨架回到同一坐标。

运镜：微距穿入一个单元 → 顺着应变能流线飞行 → 螺旋拉远看见 44 个状态 → 贴近最后一层材料的边缘完成重组。

衔接：最后一个被保留的单元边缘扩展成风浪场中的浮体边缘；不做突然消失。

### 034.0–052.0s · 把结构放回风和浪里

有了结构，还要看它在风浪里怎样运动。Zwind 求解风浪和缆绳共同作用下，平台的运动响应。这里回放保存的时程，让每个响应点都回到结构上。

画面：比例可信的浮体和系泊进入分层浪场。风向箭头沿叶片扫过，水流绕开浮体，平台做轻微纵荡、纵摇和升沉；镜头下潜看系泊张力，再回到塔顶响应点。Zwind 曲线与平台运动绑定。

运镜：海面侧向轨道 → 沿风线绕塔一周 → 穿水下看系泊 → 跟随一根缆绳上升到塔顶响应点。

衔接：响应曲线上的移动点拖出一条弧线，弧线成为下一镜网页结果图的折线；纹理、方向和速度保持。

### 052.0–065.0s · 让失败，成为下一步的反馈

真正关键的，是遇到问题以后怎么办。网格异常、求解中断，都会变成反馈，推动系统重新安排下一步；失败也要留下线索。

画面：真实结果查看器录屏：导入parameters_summary.json、适应视图、旋转已保存的三维重建。输入、日志、失败类别以来源清楚的示意轨迹伴随；不显示虚构的质量比滑杆或Run动作。

运镜：响应点引出文件路径，镜头顺着路径进入导入操作；平移经过旋转中的模型，再绕到纸面工作流。

衔接：查看器模型的轮廓匹配下一镜工程骨架；工具栏移出画面后才移除。

### 065.0–078.0s · 工具之间，有来有回

这条链路的创新，是让工具之间有来有回。模型提出调整，计算检验结果；失败原因和修改记录，都留给工程师复查。

画面：纸上工程轮廓长成参数化结构，几何、网格、BESO、尺寸与Zwind节点在相同三维路径上相连；模型建议与计算反馈走不同方向。Qwen仅用于图纸到实体概念桥。

运镜：沿图纸墨线滑行 → 纸面折起成为 3D 截面 → 推入构件内部看网格与材质叠合 → 环绕三类工具节点 → 落到报告缩略图。

衔接：报告缩略图的页边滑出画面，页边变成结果对比的基线。

### 078.0–094.0s · 结果，放回条件里看

轻量化的价值，也要放回条件里看。论文案例的单位功率用钢量，减少约百分之八点一。强度、平台运动和系泊，还需要一起检查，交给审查器逐项复核。

画面：两台风机剪影沿同一基线对齐；278 → 255.5 t/MW 的数字由报告页折成空间标尺，−8.1% 沿标尺移动。响应曲线小幅保留在背景，提醒观众轻量化不是单一目标。

运镜：从报告页基线横移 → 数字成为 3D 标尺 → 沿标尺滑向 255.5 → 回望两台剪影与响应线。

衔接：−8.1% 的短线拉直成为片尾工作流的第一段线，不做数字跳转。

### 094.0–105.0s · AI ENGINEER

AI Engineer，让智能连接工具，让计算提供依据。从需求到模型、报告，每一步都能回看。

画面：对比标尺融入风机塔架主梁，镜头从基础抬升到海平线；需求、模型、仿真、证据四个标签沿结构节点依次闭合，浙江大学标识保持右上角。

运镜：从塔底缓慢升起 → 经过构件、响应点和报告卡 → 50mm 压缩到完整风机 → 微小侧移保持 1.2 秒。

衔接：最后一个证据节点合入 AI ENGINEER 字标，海面仍在微动，声音留出半拍。

## 创新点与用途的依据

- README定义大语言模型与确定性工程工具形成验证闭环；需求阶段输出结构化任务，专家后端负责几何、网格、拓扑与尺寸优化、响应计算。
- 论文补充材料S.6–S.7描述阶段门禁、日志/指标/错误码反馈与有限重试策略。视频强调结构化重规划，不宣称每次失败均已成功恢复。
- `docs/closed_loop.md`明确区分规则评分、语言模型解释和候选决策；不允许语言模型改评分或选择未过门候选。
- 该文件列出的当前证据包仍为revise，BESO失败与原生Zwind伺服关闭的短探针被保留为各自边界内的证据。
- 三维视频工具（Three.js、Blender、Lux3D）仅服务表现，不作为AI Engineer计算创新。

## 真实网页动作

实际保留：输入需求但不提交、打开结果查看器、导入已保存参数、适应视图、旋转重建模型。不得增写滑杆改质量比、点击Run或现场求解成功。系统修改参数的潜在用途若需说明，应与录屏操作分开表达。

## 风机与融合转场

浮体保持吃水、压载、立柱和横撑的可信比例；风机、叶片、机舱和系泊共享尺度。以塔底高光、图纸墨线、文件路径和模型轮廓作为共享锚点，把海面、网页、纸面与三维连接起来。Qwen可用于同一模型轮廓在纸面中生长的概念桥，不能替代计算结果。
