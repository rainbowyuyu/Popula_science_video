# 创作记忆与双模型接力

选择左侧工程，打开「创作记忆」。默认展示自己的历史修改意见；切换「全部对话」可查看助手说明。运镜、封面、字幕、读音、故事、材质可以一键搜索。点击「查看原文与标记」查看完整内容、时间、来源行号和附件；截图在点击后才读取，原图已失效时保留路径提示。

## 怎么用于下一次创作

1. 保持「后续协作自动参考本工程记忆」开启，直接在主智能体描述这次任务。服务器会按当前问题选择历史意见，优先使用用户意见和较新的纠错。
2. 常用要求可以标为「创作偏好」，反复出现的问题标为「避免再犯」，可复用实现标为「参考资料」。备注用于写出目前仍有效的具体要求。过时要求可以「忽略」，不删除原文。
3. 勾选记录，点击「带上选中资料」，先进入主智能体草稿，再由用户发送。草稿只携带记录ID，正文由服务器重新读取。关闭自动参考后，仍可手动带上某条资料。
4. 只有明确勾选「用于整个系列」的人工标记才跨工程共享。普通历史不自动变成整个系列的硬规则。当前要求与当前系列规范优先，旧意见与新意见冲突时应核对时间与上下文。
5. 如果自动归属有误，在原文下方选择正确工程。归属纠正和忽略标记不会被再次同步覆盖。

例：`结合我之前对这一集运镜和字幕的意见，先检查当前成片的片头；保留已经做好的材质，重点修复旧问题。交接时列明对应记录、实际文件和检查结果。`

## 协作实际行为

GPT 与 Claude 共用同一份来源证据包。规划时列明采用的记录ID和验收点，实现阶段交接实际文件，复核阶段回看相应画面并说明未验证项。双方都可以用 `project_memory` 检索、分页读取原文，用 `project_memory_image` 查看记录附带的本地截图。历史模型说“完成”只算一次实现说明，不等于用户验收，更不自动关闭旧问题。

本次已完成的工作台任务，其用户要求、各阶段交接和最终说明会自动进入本工程记录。来自 Codex 的新对话通过「同步 Codex 记录」增量刷新；未变化会话跳过，变化会话重新流式索引并去重。首屏和切工程均不扫描 Codex 历史。

## 数据与边界

- Codex 原始记录只读。仅提取公开用户消息、助手进度和最终回复，不导入推理、系统提示、工具原始输出、自动续跑/心跳消息。密钥与敏感参数脱敏。
- 会话的多个分片和归档都会纳入扫描；同一长对话按工程路径、明确目标和主题阶段划分，存在歧义的保留待归类。不能用同一个仓库工作目录把所有记录塞给同一期。
- 项目目录 `.studio/codex-memory.json` 保存可追溯的工程索引与人工标记；正文统一保存在工作台 `work/project-memory/index.sqlite3`，避免每个工程复制一份大历史。备份工程时也应备份这个索引库，或者在原机器重新同步。
- 历史截图只在本地按需读取，不访问历史远程地址。截图代表当时版本，不能替代对最新成片的检查。
- 历史付费、发送、发布或删除授权不作为新任务授权。导入与检索不调用付费模型。

## 更新与验证

继续使用现有 EXE，刷新网页即可加载代码。旧启动器未包含 SQLite 时，应用从 `runtime_deps/py313` 加载当前机器 Python 自带的 SQLite 运行库，无需重新编译 EXE。该目录包含来源、哈希和 Python 许可证。

独立重同步：`python scripts/sync_codex_memory.py`。此命令不会启动模型任务或改动现有任务状态。导入报告在 `output/codex-memory-import.json`。测试覆盖去重、脱敏、归属纠错、后台增量、项目隔离、双模型共用记录、HTTP权限、附件与懒加载。
