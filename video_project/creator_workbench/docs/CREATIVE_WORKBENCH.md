## 用一个工程目标串起制作

顶部「制作简报」保存这期要讲清的问题、受众、故事主线、视觉与声音方向、保留与避免事项及可选目标时长。数据保存在当前工程 `.studio/project.json` 的 `productionBrief`。未填写的字段不构成约束，当前任务的新要求优先。

简报按工程隔离，未保存的输入暂存于浏览器。多窗口同时保存会提示版本冲突：读取另一窗口的最新内容，对照后再保存，当前输入不会被静默覆盖。运行中的任务使用提交时快照，后续任务才读取新版简报。

完整视频的制作协议强调：工程状态与相关历史 → 一句故事主线 → 旁白、镜头、资产、字幕、声音共用时间线 → 代表镜头 → 逐段实现 → 检查与修复。局部读音、字幕、材质或单段镜头修改直接定位处理，不强制重做整片。时长服从当前要求和实际旁白。

制作策略见 `app/creative_prompt.py`，技能入口为 `skills/video-creative/SKILL.md`，详细工作法按需读取其 references。它们是本项目编写的行为指导，不能改变模型本身的能力、连接未配置的服务，也不等于复制 Codex 隐藏提示词。

## 反馈与核验

主智能体显示一张持续更新的任务卡，保留目标、当前事项、步骤、本次成果及核验。原始要求、完整回复和工具记录仍可展开查看。过往任务按需读取，轮询保留已展开内容、焦点和滚动位置。

GPT 与 Claude 共用 `run.creativeWork`：

- `update_work_plan` 更新真实工作项及状态。
- `report_artifact` 验证路径、文件类型和存在性，保存哈希，并为支持的媒体登记预览。
- `record_check` 引用服务器产生的工具证据。检查记录保留范围与局限，不能凭一句“已检查”伪造通过。

自动命令检查、静帧抽查、模型判断和实际听审分别展示。文件存在不等于验收通过；`final` 只是申报用途。静帧通过不表示全片已经连续观看。检查和产物版本绑定，旧帧不能证明新文件已验收。

模型结束本轮，但自建计划还有待办时，显示「本轮结束 · 仍有待办」及剩余项。不会自动把未完成步骤打勾。可以从主输入框继续提出要求。停止与恢复仍使用既有检查点机制，不自动恢复用户已暂停的任务。

## 联动与预览

封面、声音、镜头、记忆和整理模块共用下方主智能体。当前模块设置自动进入上下文；显式选中的帧、区间和修改意见优先。「带上当前设置」整理为草稿，用户点击开始后提交。镜头实现按钮也先进入主智能体草稿。

新成果和后台任务完成只更新媒体索引，不替换正在看的视频、音频或图片。点击成果才打开预览；窄窗口自动切到成片预览页。模块任务反馈以状态卡显示，技术详情折叠；同一媒体在反馈更新时保留播放器节点，避免暂停。

封面页首先展示当前工程最新各比例封面。现成图片作为完整输出预览，修改入口将其作为参考交给主智能体；新封面草稿与已有烘焙文字分开，避免自动重复叠字。四比例画布、发布文案和系列批量功能继续使用原工程数据。

工作台、双栏协作、成片预览按窗口尺寸记住视图。原有分栏拖拽和右键菜单保留。学习工作室独立运行，提供参考库/学习成果和队列状态筛选，核验轮次和路径按需展开，样片点击才加载。
