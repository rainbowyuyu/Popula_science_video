# 视频制作手册

此手册为本工作台编写，采用公开软件代理常见的工程方法：读取上下文、小步实现、检查实际结果、保存进度与明确交接。它不复刻任何产品的隐藏提示词，也不要求记录私有推理过程。

## 选择最短的完整路线

先判断完整新片、结构重构、局部修复或独立附件。目标决定检查范围，阶段名称不扩大任务。

| 请求 | 先读什么 | 应做的工作 | 完成依据 |
|---|---|---|---|
| 新片或整片重构 | 受众、素材、事实、品牌、已有工程能力 | 主线、时间线、小样、逐段制作、整片整合 | 实际成片、来源、逐段与音画检查 |
| 某段镜头或机制 | 指定时点、标记、原入口、相邻段 | 修复根因，渲染目标与边界 | 可对照的片段与衔接检查 |
| 字幕、读音或单处文字 | 字幕源、口播源、目标音轨/画面 | 修正数据，重新生成必要部分 | 字形/发音及同步检查 |
| 音乐 | 指定曲目、旁白、旧混音结构 | 乐句衔接、音量动态和尾收 | 可试听音轨与声学检查 |
| 封面/发布文案 | 真实内容、系列规范、代表画面 | 按比例构图或分平台编写 | 可打开的输出与源布局 |

不把字幕修正扩展成调研、全片重写和再建模。小任务计划可只有两三步；已完成的事实直接沿用。

## 1. 起点和验收点

读取 `project_state`、本次标记、README/package/入口、最新成片与相关历史意见，只进一步展开当前问题需要的源码和素材。确认哪份是当前结果，哪份是旧缓存；找不到入口先搜索路径，不凭文件名猜。

用一两句话说明目标与尺度，例如：“保留第42秒的模型，只修正插销方向；检查装配过程和两侧转场。”加入可观察验收点：沿孔轴进入、不穿插、标签避开孔口。完整片再补观众、主线和时长。

历史只提供线索。引用用户纠错ID；旧模型说“完成”需要打开文件/画面核实。当前选择优先，忽略记录与未启用的系列规则不可自行恢复。历史费用、发送、发布和删除授权不用于新操作。已授权范围内的读取、可逆修改和常规实现不逐步询问，缺失关键信息才集中澄清。

## 2. 把知识写成发生的事情

先用一句话讲清“谁遇到什么问题，试了什么，结果怎样，观众最后懂什么”。这是因果主线，不是标题、知识目录或术语集合。

例如指针可从“两个标签写着同一地址，改一个地方为何另一处也变了”发展到地址、间接访问和共享对象。术语出现在观众已看到变化之后；比喻有边界，回到实际内存关系时交代对应关系。

每段增加理解：看得见的问题 → 一次尝试及反馈 → 造成结果的机制 → 回到开头问题。不要均分所有段落时长。复杂动作留观察时间，已解释的术语不重复介绍。读通口播，删去空泛赞叹、重复反问和机械的“不是……而是……”。健康/工程等事实核对来源，不为故事编造结论。

## 3. 一条共用时间线

旁白、模型、相机、文字和音乐不能各自估计时间。沿用现有格式，没有时写可检查JSON/CSV，不为格式重构工程。每段至少记录：`id`、`start/end`、旁白源句/实际TTS时长、动作、焦点、`anchorIn/anchorOut`、素材路径、字幕、声音节点、证据类型与来源。用同一ID关联，避免散落重复时间常量。

先校对术语、多音字和缩写，再生成或局部替换TTS；显示字幕保持正确写法，发音辅助单独保存。按实测时长安排动作与停顿。用户允许延长时以讲清为目标，不能靠不自然加速硬塞五分钟。

镜头描述要可实施：“沿孔轴推进，前壳逐渐透明，插销从右侧入画”，不要只写“高级丝滑”。统一单位、坐标与装配方向。材质、灯光、遮挡和景深帮助看懂形体，不把关键机制藏进前景或虚化掉。

## 4. 先做能暴露问题的小样

挑开头钩子、关键机制、跨尺度或复杂转场等质量风险最高的一段。复用资产做低成本关键帧和短片，确认观众不读长文字能看懂变化、标签不遮挡、空间和尺度可追踪、材质阴影支持形体、声音与动作同步。

失败就修最小根因。一次有效检查通过即进入制作，后续改动未影响它时不重复生成。小样不是必须请求用户批准的关卡；在现有授权内完成检查继续。

## 5. 逐段实现与模型交接

沿同一时间线逐段做。主体用运动、遮挡或焦点把观众带到下一段；跨尺度保留定位依据。前层透明帮助转移注意力，不依赖整屏淡出掩盖未建立的空间关系。相机不必不停旋转，解释任务优先让观众看清。

角色是优先主导，任何模型都可以修复根因所在层。交给协作者的任务应含：

```text
目标：修复42—49秒插销装配与孔口可读性。
已确认：scene.ts中孔轴为局部X；相邻段使用joint-A锚点。
实际文件：src/joints.ts、src/camera.ts；小样output/joint-preview.mp4。
边界：保留旁白时长和孔尺寸；同一入口串行修改。
验收：沿孔轴装配；无穿模；48秒标签不遮挡孔口。
返回：修改文件、观察帧/时间点、检查结果、未核验项。
```

接手先看文件与证据，保留有效实现。接口或主线确需改变时说明具体原因与影响。原主导读取返回产物并继续完成任务。阶段轮数是执行窗口，到达窗口保留进度接续，不把未完成包装成交付。

## 6. 工作板与证据

若当前工具清单提供下列工具，按实际schema记录；不可用时写工程工作记录，不虚构调用。

- `update_work_plan`：`goal`、`steps[{id,title,status,phaseId,verification,note}]`、`currentStep`。步骤按ID更新，不反复创建同义步骤；状态是当前事实。`verification`引用已有检查ID。
- `report_artifact`：`path,title,kind,stage,checkIds`。文件需真实存在于当前工程/独立版本工作区；`stage`可为draft/preview/final，登记final仍不等于通过验收。
- `record_check`：`title,kind,status,evidenceIds,scope,note,stepId,artifactId`。仅引用工具实际返回的 `evidenceId`。自动检测、静帧抽查、听审、人工和模型审阅分开，服务器判定证据是否有效；文字自报不能冒充已验证。

工作板呈现目标、步骤、当前进度、产物和检查，便于用户边看边改。进度只写新发现、正在修的点、下一项检查；命令长表、失败详情放日志。工程摘要可以说明已采取的选择及依据，不要求展示隐藏推理链。

## 7. 检查、修复与交付

源码检查证明能编译，解码证明文件可读，静帧证明某帧美观，连续片段才能检查运动转场，实际听审才支持音色与断句判断。任何单项都不能代替其他项。

完整片检查尺寸/帧率/时长、音画首尾、黑帧/长静音、峰值、字幕、各段与转场。局部修复验证目标和两侧边界，并核对区间外是否受影响。保存命令、退出码、时间点与观察。只有新修改、失败或未解决的问题才继续检查，不无意义重跑通过的检查。

交付先给最新成片/小样或附件路径，再说明源码与实测结果。保留可重渲染入口、素材、音轨、字幕、来源与日志。未生成成片称源码或小样；只抽帧称抽帧检查。清理仅按明确清单和引用关系，保留回退，不修改别的工程和共享依赖。
