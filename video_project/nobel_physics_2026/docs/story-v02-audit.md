# V02 故事与字幕审查

审查范围：`docs/story-v02.md`、`src/physics2026/timeline-v02.json`、`src/physics2026/FilmV02.tsx`。本文件只记录审查意见和可选文案，不改写 V02/V03 成片。

## 先修的结构问题

### 1. 从颁奖名单跳到物理问题少了一步

`001 → 002` 现在从“得主是一人，IceCube 是十四国合作团队”直接问“为什么要找中微子”。观众还没有看到这项工作的目标。建议把 `001` 结尾换成：

> 奖杯上只写着一个名字，真正把这束光接住的，却是一支跨越十四个国家的团队。那他们究竟在冰里等什么？

这样 `002` 的“为什么要找中微子？”就成为自然追问，画面也可从合作网络收束到一条中微子轨迹。

### 2. `002` 和 `003` 有内容重复，应分成“动机”和“视觉对照”

`002` 已经解释带电、吸收和直线飞行，`003` 又用相同三句话重述一遍。建议保留 `002` 的因果，只把 `003` 改为观众可以看懂的空间实验：

> 把三种信使同时从左边放出去。质子被磁场拽弯，伽马射线在尘埃里逐渐熄灭，只有中微子还沿着原来的方向前进。它最难抓住，却最像一封没有改过地址的信。

末句是比“保留了最干净的来路”更口语的比喻；画面应让三条路径真正分开，不能只换标签。

### 3. `004 → 005` 缺少“为什么冰能做望远镜”的桥

在统计规格出现前，增加一句因果：

> 既然中微子很少留下痕迹，探测器就不能只做得精密，还得做得足够大。Halzen 和 John G. Learned 想到的答案，是把南极深冰直接变成望远镜。

随后再展示 86 条串、每串 60 个模块和近 1 km³；这些数字应跟着镜头逐项出现，不要在同一帧堆出四个数字。

### 4. `006 → 007` 术语跳得快

Cherenkov 光锥出现前建议先用一个短类比：

> 就像飞机超过音速会留下锥形音爆，带电粒子超过光在冰里的速度，也会留下一个光的圆锥。

随后再显示 `v > c/n`。公式的口播改成“粒子速度 v，大于光在冰中的速度 c 除以折射率 n”，比逐字读“速度 v 大于光速 c 除以折射率 n”更不容易让人误解为真空光速。

### 5. `011 → 012` 应把“统计证据”转成“寻找来源”的下一步

`011` 的结尾建议改为：

> 这时，蓝光不再是一次偶然闪烁，而是一组足以和背景分开的事件。下一步的问题变成：它们究竟从哪里来？

`012` 再分别展示两个线索，避免 25 秒连续报数字：

> 2017 年，一次约 290 TeV 的事件落在耀变体 TXS 0506+056 的方向，误差圈约 0.06 度。2022 年，NGC 1068 方向又出现 1 到 10 TeV 的过量，显著性约 4.2 个标准差。它们是有力的候选线索，仍然不是“唯一答案”。

其中“误差圈约 0.06 度”比“差约 0.06 度”更清楚；画面可以先聚焦 TXS，再平移到 NGC 1068，中间不要重新淡入整套标题。

## 口播语气微调

- `001` 的“授奖理由是”偏公文，可改为“委员会给出的理由很具体：……”。
- `006` 的“我们看到的是间接回应，不是把中微子直接拍下来”保留事实边界，但可说成“所以画面里的蓝光，是它留下的回应，不是中微子本身”。
- `008/009` 首次出现时先说中文，再补英文：`长径迹（track）`、`簇射（cascade）`；后续只保留中文，避免中英来回切换。
- `010` 的“发现从来不是一颗亮点，而是整组事件胜过背景”可改为“真正的发现，靠的是整组事件一起把背景压下去”，更像主播口吻。
- `013` 的“Halzen 的贡献，是……”与 `001` 重复，建议改为“要让这个想法常年工作，难点又回到了工程现场：钻孔、布线、校准和筛选数据……”。
- `015` 的“科学最诚实的地方”略像总结模板，可改为“所以结论只走到证据允许的地方：看见了什么写什么，还不能确定的也留下来”。
- `016` 的“可能就是亿万光年外的一次相遇”可以保留诗意，但前一句应落回实验：“下一次亮起的轨迹，我们还会继续追它的方向。”

## 字幕与标题实现风险

1. `FilmV02.tsx` 的 `wrap()` 最后使用 `lines.slice(0,3)`。这会在未来出现长字幕时静默丢行；应改为完整返回 `lines`，并让字号或最大宽度在 1–2 行与 3 行之间自适应。
2. `Caption` 使用 `whiteSpace: 'nowrap'`。如果需要两行，应该让每个意群成为一个稳定行，而不是在同一行里不断重新换行；不要用每帧测量文字宽度造成抖动。
3. `Header` 的 `q` 每个 clip 从 0 重新开始，标题在 17 个场景交界处都会重新滑入。建议保留品牌和总章标题，只让小标题做一次 8–12 帧的横向位移；桥接视频期间不要把标题整块重置。
4. `Source` 在每个片段重新出现。来源信息应在第一次出现后短暂停留，再渐隐；跨片段的同一来源不要反复闪入，避免抢过主体。
5. `001`、`004`、`012` 字幕中英文混排较密，建议给英文专名固定字重和不换行容器，中文意群独立计时，避免英文拉宽整行导致遮挡。

## 建议的画面—口播节奏

每个片段按“问题出现 → 一个可见变化 → 结果稳定 → 镜头离开”组织。尤其是：

- `002/003`：三条路径先同起点，再分别弯折、衰减、直行；不要先显示三张静态卡片。
- `005`：镜头沿一条探测器串下潜时，数字按空间位置出现（86 条 → 60 个模块 → 深度 → 1 km³）。
- `007`：先让光锥形成，再把 `v > c/n` 放到光锥旁边；公式停留至少 1.2 秒后再淡出。
- `008/009`：track 用一条有时间顺序的光点链，cascade 用同一碰撞点向外扩散的簇射；两者不要同时满屏。
- `011/012`：先用 5.7σ 的曲线稳定下来，再把视线沿方向线移到候选源，避免数字和地图同时闪烁。
