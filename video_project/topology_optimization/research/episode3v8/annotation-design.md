# v8 构件与结果标注设计

本稿只定义名称、真实几何锚点和显示原则，不改动视频源码，也没有渲染。依据现有 v7 模型和求解结果核实；v8 新配音时长与新运镜确定后，应按语义事件重新定时，不能照搬旧绝对帧号。

## 已核实的模型与坐标

- 模型有 117 个真实部件。依据 `research/episode3v7/pavilion-manifest.json`、`public/episode3v7/models/pavilion-manifest.json` 和 `../episode3/build_pavilion_v7.py`。
- Three.js 坐标是米、Y 向上；Blender → Three 为 `[x,z,-y]`。下表全部使用 **装配完成时的 Three 世界坐标**，不是 glTF 节点局部坐标。
- `World.ts` 导入时把源网格的世界矩阵烘焙进顶点。每个 `part.root` 再添加本件的拆装偏移；标注必须跟随自己的 part，不能统一借用柱子的偏移。
- 榫和榫肩是穿梁 `CROSS_FRONT` 的一部分；卯是柱 `POST_FL` 中的槽口；销是独立部件 `PEG_X_FL`。三者不能用同一个锚点。
- `J_X_FL` 的接头中心是 `[-1.5,3.0,1.5]`，穿梁榫截面为 0.10 × 0.14 m，卯口截面为 0.1016 × 0.1416 m。柱头另一方向的卯在 y=3.42 m，不能混标。
- 木销半径 0.014 m、长度 0.34 m；其轴线是 Three Z 方向。插入时先从正 Z 侧靠近，不能用竖直下落的标记误导。
- `BENT_FRONT` 是一组构件的 `parent` 分类，不是实际网格；“一榀”必须说明一组梁柱，不能把某一根梁单独标成一榀。
- `DECK_FRONT` 才是望板；`TILE_FRONT` 是灰瓦屋面。不能把瓦面标成望板。

## 取舍与节奏

主线只做七组认知动作：**榫／卯 → 榫肩 → 木销 → 一榀／纵枋 → 斗栱 → 角梁／椽／望板 → 受压受拉／应力／位移**。每一组按解说逐个出现，不做零件名词墙。同屏最多两个名称；通常只留一个。

“斗、栱、承檩斗”不再逐一加第三层术语；说明整组关系时标“斗栱”。“檩”在 v8 新的受弯特写中确实需要命名时，先标一次“檩”，后面让“受压／受拉”取代它。术语不出现拼音、小号英文和三行解释。名字后的解释交给声音和动作。

片头爆炸视图不贴满名牌，让观众先看亭子怎样打开；首个接头推近完成后才解释榫与卯。章节大标题与贴体标签错开时间，不争夺同一片留白。

## 有符号应力的独立核算

采用现有 `frame-contract.json` 和 `physics/static-cases.json` 的真实梁端力，按 `StressField.ts` 的 `N/A + My·z/Iy − Mz·y/Iz` 独立计算。已与 model_rebuild 沟通：v8 重力段选 `PURLIN_Y_LEFT`，element 177，s=0.5。

| 探针 restThree | 独立算得正应力 | 应显示 |
|---|---:|---|
| `[-1.50,4.14,0.396]` | −0.0222635904 MPa | 受压 |
| `[-1.50,4.00,0.396]` | +0.1895398784 MPa | 受拉 |

这两个点是截面宽度中线的上、下纤维，和截面角点最大值不同。标签不可把 +0.18954 MPa 写成“该梁最大应力”。数值由渲染当前求解结果读取；表格仅是来源核验。

旧 `CROSS_FRONT` 也说明为何不能把整根梁一概标成上压下拉：x=−0.10 m 的上、下纤维分别约 −0.007466 / +0.015478 MPa；x=−1.20 m 却约 +0.023592 / −0.009424 MPa。先看真实符号，再放名牌。

梁截面应力不是卯口局部接触应力。卯口压力、木销约束可以用受力示意和名义需求说明，但不能用未求解的红斑冒充孔边应力集中或破坏结果。

## 屏幕排版与动效

- 1920×1080 基准：构件名 48 px，统一宋体风格和中等字重；最多一种补充字号 40 px，仅用于必要单位或放大倍数。不要另加 24 px 小注。关键名词保持 2–5 字。
- 标注墨色沿用深松绿 `#293b32`；引线可用较深暖金 `#967044`。拉压严格沿当前物理色标使用青／赭红，不临时增加荧光色。
- 优先无边框文字。背景复杂时用轻薄纸色底托，不能做沉重卡片、投影大框和 HUD。模型关系是主角，标签是旁注。
- 引线 2.5–3 px、端点 4–5 px，常用长度 28–120 px，最多一个折点。标签贴近对应局部，不能从画面边缘横拉半屏线。
- 两个标签不得交叉引线。只允许指定的一组相对位置；不要每帧左右跳边。遇到碰撞先调整镜头或延后展示，不能把文字强行压小。
- 保留左上 logo/`rainbow鱼`。品牌初始禁入区为 x=48–500、y=32–156；章节标题、底部字幕、色标的实际 DOM 边界另作为动态禁入区。字幕留出 y≥930 的安全带。禁入区还需向外扩 16–24 px。
- 画面边缘安全距离 64 px；标签盒须完全在画内，锚点必须落在可视的真实部件表面。不能只把文字 clamp 在边缘，留下指向画外的错误引线。
- “出现”配合构件入镜或镜头停稳：0.25–0.4 s 小幅平移定住，至少清楚停留 1.8–2.5 s，再随下一次镜头移动离开。两字名称也要让人有时间看回木头。
- 不用透明度淡入淡出充当转场。整组标签跟随被解释部件的屏幕运动；下个对象进入前，旧名牌先沿既定方向移出镜头，完全越过画框之后才可卸载。若物件仍留在镜头，标签单独出画也要有 0.5–0.8 s 的完整出场路径。
- 框内出现遮挡时不能突然关闭 visible 来掩盖：先利用镜头、抬件或局部透明保证约定的标注窗口，再把标签移出画面。遮挡检测是排程失败信号，不是让文字闪现的开关。
- 不做每帧依赖上一次状态的弹簧追踪。Remotion 并行渲染需要按绝对帧确定性计算位置；动画、出场和候选选择必须可随机访问。

## 与模型端的接口约定

model_rebuild 计划提供 `getAnchor(partID, restPointThree)` 和 `getAnnotationAnchors(state)`。建议锚点返回：

```ts
type AnnotationAnchor = {
  x: number; y: number;
  world: [number, number, number];
  partID: string;
  visible: boolean;       // 正向相机、在视锥与屏幕内
  occluded: boolean;      // 对实际亭子网格射线检查
  opacity: number;        // 被指部件材料状态，非标签淡入淡出
};
```

1. 在装配态网格上找到候选点最近三角形和重心权重，缓存绑定。
2. 每帧读取该三角形当前实际变形顶点，按权重求锚点，再应用本 part 的装配偏移和祖先矩阵。不要重复应用 rest_matrix。
3. 使用本帧已更新的相机矩阵投影；不要用前一帧相机或只用 CSS 平移猜测锚点。
4. 通过透明构件看里面时，把明显透明的遮挡体与不透明前景分开处理。材质透明并不自动保证目标可辨识，最终仍要看图。
5. 空洞中心不能绑定最近任意三角面；卯口明确使用上唇的真实点。组标签另传 `memberIds`，不能伪造单个组网格 ID。
6. 物理结果同时返回名称、单位、真实值、放大倍率和对应的有符号/幅值模式。`位移 ×N` 必须取实际 displayGain；不把显示放大后的长度当真实位移。

## 运镜约束与验收点

旧镜头的纯数学投影暴露两个风险：旧 frame 3885 中，`HIP_FL` 的中段候选点约在 x=97；旧 frame 4350 中，中心椽候选点约在 y=59。它们靠边或将出画，不能照抄固定标签坐标。v8 需要把相应构件提前运进安全区；镜头还未就位时先延续动作，不抢先说新词。

下一阶段对新视频逐组检查：

1. 第一词之前 0.4 s、第一词当帧、停留中点、出场开始／中点／完全离场后各看一帧。
2. 检查引线端点是否仍在正确实体、拆件偏移和形变是否同步；木销、卯口和屋面分层重点检查。
3. 两个有符号应力名牌必须与同帧探针符号相符，且对应表面没有被不透明屋顶挡住。
4. 榀是成组梁柱，斗栱是一组柱头部件；椽、望板、瓦不得互相错指。
5. 每个新章节的大标题在靠近木料前完整出画；入场途中也应避开先前发现的 1906/2855 类“标题擦过木构件”。
6. 看 320 px 缩略图仍能分辨名字和被指对象；文字与物件之间是清楚的关系，而不是图上堆出的字。
