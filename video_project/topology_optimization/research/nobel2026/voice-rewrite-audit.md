# 诺贝尔生理学或医学奖旁白重构审计

审计日期：2026-10-05

## 当前版本的可验证问题

1. `src/nobel2026/timeline.json` 的 `text` 与 `spoken` 不是同一份文字。画面字幕使用 `text`，旁白使用 `spoken`，因此会出现“2026 年/二零二六年”、英文姓名/中文读法、英文术语/中文术语不同步。重构时每条 clip 应只有一份 `subtitle`，并让 TTS 输入和字幕都从这份字段生成；英文原名只留给画面名牌。
2. `scripts/voice_nobel2026.py` 根据固定视觉窗把音频拉伸，`ratio` 被限制到 `0.80`。当前音频的源时长与窗口比值最低约 0.52，意味着部分句子被放慢约 25%，再用填充承接剩余画面，听感容易拖沓。新版本应先按自然语速安排文案，`atempo` 只允许 0.95–1.05，超过范围就改文字或改镜头长度。
3. `audio-manifest.json` 仍引用已经删除的 `public/nobel2026/voice/*.wav`，而旁白审计记录引用 `voice-raw`。交付版应只保留实际存在的 `master.wav` 和新的 `voice-lines.json`，或在交付前重新生成一份不含失效路径的 manifest。
4. 现有文字没有讲出官方科普页里的关键验证：通道在蛙卵膜上约 0.2 ms 打开、2003 年将 ChR2 引入人胚胎肾细胞和仓鼠肾细胞、2007 年运动皮层控制小鼠胡须、同年唤醒小鼠、2012 年重新激活恐惧记忆痕迹。画面应按这些实验逐步推进，不要只用抽象的“脑区亮起”。
5. 现有字幕算法按长度动态切句，可能在逗号处切断完整意思。建议在文案中显式给出 `subtitleParts`，每条 12–22 个汉字、按自然停顿出现，旁白和字幕共享同一组句子。

## 音频重生成与逐句 QA

- TTS 输入、字幕和人工审听稿必须来自同一 JSON 字段；英文原名不进入旁白。
- 每条 clip 先按 4.0–4.8 个汉字/秒估算，允许自然停顿；禁止用 `atempo < 0.90` 补齐画面。
- 人名稳定读法：卡尔·迪塞尔罗思、彼得·赫格曼、格奥尔格·纳格尔；`channelrhodopsin-2` 旁白读“二型通道视紫红质”，`optogenetics` 旁白只读“光遗传学”。
- 数字稳定读法：零点五毫秒、零点二毫秒、二零零三年、二零零五年、二零零六年、二零零七年、二零一二年。
- 每条旁白生成后，用 Whisper-small 做漏字、重复字和专名抽查；机器转写只作筛查，最终以人工逐句听审为准。
- 检查每条音频的首尾静音、削波、异常拖长和跨 clip 溢出；任何句子越过视觉窗超过 120 ms 都应重写或调整镜头。
- 最终响度建议旁白整片约 -18 LUFS、True Peak ≤ -1 dBTP；背景音乐在旁白期间至少低 16–18 dB，并在句间短暂抬升。
- 片尾论文/官方资料展示至少停留 8 秒，论文图、标题、作者年份分层呈现；不把示意图写成实验原图。
