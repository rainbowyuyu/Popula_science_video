# 地铁进站与站台安全线：可复现的原理演示数据

运行 `python scripts/physics_metro.py`。依赖 NumPy 与 Numba；本机 CPU 足以完成，本次未使用远程 GPU。

## 求解与用途

`public/metro/physics/flow.json` 来自 D2Q9 BGK 格子玻尔兹曼求解，而非预画的粒子路径。几何是长 8、宽 1.3 的圆端二维车体俯视轮廓，车头 x=-4，车尾 x=+4，轨道沿 x，横向为 z；Three.js 的 y 为高度，二维求解没有这个维度。来流在**随车参考系**沿 +x，世界系车体向 -x 行驶。

这是 Re=20 的简化教学模型，解析车头绕流、车侧流动与尾流恢复。它不是全尺度地铁 CFD，不包含隧道、站台壁面、车顶、制动或乘客；不能据此预测站台真实风速、人体失稳概率或安全线距离。侧边界位于 z=±6，采用自由滑移边界，有限域阻塞对结果有影响。画面使用“随车观察 · 简化流场”，不要称为“真实车站风速预测”。

## 渲染接口

- 网格索引 `i=iz*nx+ix`，位置为 `x=x0+ix*dx`、`z=z0+iz*dz`；`solid[i]` 为车体掩膜。
- 每帧 `u[i]`、`v[i]` 是随车坐标中的流速，分别沿 x、z，以入口速度归一化。
- **站台参考系气流速度应为 `(u-1,v)`**，不能把随车速度直接当成乘客感到的风速。
- `cp` 为压力系数 `(p-p_upstream)/(0.5 ρ U∞²)`。显示可裁剪颜色范围，原始数值不可裁剪。
- `time` 为 `t*=t U∞/D`；这是无量纲时间，不能宣称对应实际地铁进站秒数。
- `streamlines.json` 的 `snapshots[].lines[].points` 为 RK4 积分后的 `[x,z]`。每条 140 个点；可放在 y=.85 的同一检查平面。`arrivalTime` 是沿积分轨迹的时间坐标，可用于变速粒子；`arcLength` 是累计弧长。粒子只能在视野外从末端回到入口，不能用一段可见直线连接首尾。
- 相邻流场样本已有相同 seed 和点数，可插值位置。插值只是回放展示，不是新增计算。不要添加未求出的螺旋或把低 Re 尾流称为湍流。

`passage.json` 将最终流场相对一个固定观察点平移，比较距车侧不同**模型距离**处的速度经历。它是准稳态派生演示，不是另一次移动边界求解。xRelative 从 -9 增加到 +13 时，观察点依次看见车头、车侧与车尾经过。所有距离均为模型坐标，不可标成真实安全距离“米”。

## 活塞效应与人体受力

`piston.json` 独立展示体积守恒 `Q=A_train V`，然后按明确假设的 30% / 25% / 45% 分到通风道、站台开口、车体旁绕流通道。三路流量之和逐帧等于排开体积率；比例与面积只是教学设定，不是车站测量。不能说所有被排开的空气都吹向乘客。

`balance.json` 独立计算 `F=½ρC_DAu²` 与 `M=Fh`。输入为假设的均匀来风，与低 Re 流场无量纲数据不作未经验证的物理尺度换算。它说明风速增加时气动力如何变化，不计算摔倒阈值。人体摆动若加入画面，须理解为动作演示；该模型没有平衡控制、足底摩擦、握持或反应行为。

## 审计

`physics-audit.json` 记录求解器版本、输入边界、两级同 Re 网格、密度及 Mach 范围、流量检查、后期质量漂移、探针速度变化与数据哈希。两级网格探针检查只给出敏感性，不声称完成严格的网格无关性研究。最终数据必须通过代码中声明的检查才可用于成片。

安全站位结论必须依据运营方规则：站在安全线远离轨道的一侧，候车时不越线，不倚靠屏蔽门；遵守当地站台标识。此物理演示不替代运营规则。
