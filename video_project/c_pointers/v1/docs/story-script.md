# C语言指针：为什么加了分，原来的7没变？

声音：rainbow鱼个人音色。配乐：用户指定《Hypnotic》。本文件按源句列出，不替代实际合成时长。

## s01 · hook

游戏终于过关，计分板却卡在七分。加分代码明明执行了，画面上也闪过一个八，分数怎么还没变？

画面：游戏关卡完成，7分计分板与函数内部短暂出现的8分并列；主板仍为7。

动作：score_stuck

```c
score = 7; addOneWrong(score);
```

## s02 · hook

我们先把游戏暂停。加分函数收到七，把七改成八，接着退场。问题就藏在它收到的那份东西里。

画面：沿分数数据飞入函数舞台，副本7变8，原7持续可见。

动作：copy_enters

```c
void addOneWrong(int n) { n++; }
```

## s03 · hook

你把分数抄在便签上，交给朋友加一。朋友把便签改成八，墙上的计分板当然还停在七。

画面：原分数像实体计分牌；复制件沿轨道到函数，不让原件也改变。

动作：copy_revealed

```c
addOneWrong(score);
```

## s04 · hook

想改墙上的分数，得让朋友找到那块计分板。今天说的指针，就从这一次白忙活的加分开始。

画面：函数副本滑出，原计分板拆出内部存储位置，镜头连续进入。

动作：follow_original

## s05 · memory

把电脑内存想成一排有门牌的格子。数据住在里面，地址告诉我们，该去哪里找它；名字则方便程序认出这个变量。

画面：内存格从计分板下铺开，单一高亮score格；地址牌和内容分层。

动作：reveal_memory

## s06 · memory

现在建一个保存分数的整数变量，先放入七。给它取名，之后程序就能通过这个名字找到它，读出分数。

画面：score标签、格子中的7和真实C代码依次对应。

动作：store_seven

```c
int score = 7;
```

## s07 · memory

七是格子里的内容，地址是格子的位置。就像快递箱和收货地址，搬进什么东西，门牌还在那里。

画面：镜头从格内7移向固定门牌，内容与位置不同颜色。

动作：value_address

## s08 · memory

这些十六进制门牌是为了讲解画的，真实地址每次运行可能不同。记住内容和位置的区别，不用背这串号码。

画面：地址只示意0x1000，短标签“示意地址”；不声称是真实进程地址。

动作：address_note

## s09 · address

接下来拿到分数的地址。代码里的这个与号，放在变量前面，就像问它：你具体住在哪儿？

画面：&从代码沿路径指向score门牌，门牌内容被读出。

动作：take_address

```c
&score
```

## s10 · address

地址也得有地方保存。我们另开一个格子，取名 p，把分数的地址放进去，这就有了一个指针变量。

画面：独立p格出现于同一内存阵列，内部存0x1000；光路连向score。

动作：store_pointer

```c
int *p = &score;
```

## s11 · address

看清楚，p 里面装的是地址，分数仍然留在原位。两者没有合并，指针也有自己的存储位置。

画面：拉开两个格子，p格与score格尺寸一致，地址通路固定两端。

动作：two_objects

```c
p = &score;
```

## s12 · address

声明中的星号说明，p 是指向整数的指针。类型告诉程序，沿这个地址过去，要按什么类型访问。

画面：代码中int与星号分别强调，沿路径出现整数轮廓，不增加第三格。

动作：pointer_type

```c
int *p;
```

## s13 · dereference

现在沿着p 保存的地址出发，找到分数那个格子。把星号放在 p 前面，表达的就是这次访问。

画面：镜头跟随一颗光点从p出发到score内的7，星号成为路径起点。

动作：follow_pointer

```c
*p
```

## s14 · dereference

这叫解引用，名字有点拗口，动作倒很直白：看地址，找位置，访问那里原本放着的东西，途中不用再抄一份分数。

画面：地址牌高亮、路径亮起、目标格开合，分三拍对应而非同闪。

动作：dereference_steps

```c
*p
```

## s15 · dereference

读星号 p，会读到七；给星号 p写入八，变的就是原来的分数。计分板这回跟着跳到了八。

画面：写入光束沿p路径到score，score和远处计分板同步7到8。

动作：write_through

```c
*p = 8;
```

## s16 · dereference

如果把 p改成奖励分的地址呢？顺着地址找过去，发现它换了访问目标，原来的八分仍旧待在原地。

画面：bonus格20进入邻位，p值换址，路径平滑转向；score保持8。

动作：retarget

```c
int bonus = 20; p = &bonus;
```

## s17 · dereference

所以，改 p是在换地址；改星号 p，才是改地址指向的内容。分清这两件事，指针就不容易看晕。

画面：先仅路径改向，再沿新路径把bonus20改21，score不动。

动作：pointer_vs_value

```c
p = &bonus;  *p = 21;
```

## s18 · function

回到那次加分失败。分数重新设为七，旧函数收到的是七的副本。副本变成八，原件没有被碰到。

画面：同一计分板复位7，函数格副本变8；原件保持7。

动作：retry_wrong

```c
score = 7; addOneWrong(score);
```

## s19 · function

现在把函数改一处：让它接收一个整数指针。调用时交给它分数的地址，地址也会被复制一份。

画面：函数入口接住地址副本，原内存对象持续存在，函数中另一个p格。

动作：pass_address

```c
void addOne(int *p); addOne(&score);
```

## s20 · function

这个细节很关键：C语言传参数，传的都是值。传进来的可以是七，也可以是指向七所在位置的地址。

画面：并列展示数值7副本与地址副本，但保持一个主焦点先后切换。

动作：all_by_value

## s21 · function

两份地址，找到的是同一个分数。就像你和朋友各拿一张同样的门牌，最后敲开的还是同一扇门。

画面：函数内外两份地址路径汇到同一score格，不把两个p对象合并。

动作：same_target

## s22 · function

函数先沿地址找到分数，再把它加一。屏幕上的括号把这两个动作圈清楚：访问内容，然后加一。

画面：先亮*p目标格，再亮++，7变8，不移动p。

动作：increment_target

```c
void addOne(int *p) { (*p)++; }
```

## s23 · function

函数结束，那份临时地址退出舞台，改好的八分却留下了。开头那一分，总算加到了该加的地方。

画面：函数局部格滑出屏幕，score8仍存在，计分板响应成功。

动作：function_returns

```c
addOne(&score);
```

## s24 · array

游戏还有三名队员。把他们的分数排进一个整数数组，同样类型的元素，会连续摆在内存里。

画面：score格镜头滑向三格数组，7、8、9与索引0、1、2清晰对应。

动作：array_three

```c
int scores[3] = {7, 8, 9};
```

## s25 · array

让指针指向第一名。现在给指针加一，它会去第二名的位置；第一名的分数，可不会因此多一分。

画面：指针目标从索引0滑向1，数组数值不变，避免箭头穿越格子。

动作：next_element

```c
int *p = scores; p = p + 1;
```

## s26 · array

这里的一步，是一个元素的跨度。这次运行，整数占四个字节，地址就走四格；换个平台，大小还可能不同。

画面：每个整数格下分四个字节；标“本次实测”后引用验证数据。

动作：stride

```c
p + 1
```

## s27 · array

为什么要告诉程序，指向的是整数？类型就在这里派上用场：下一项有多远，要按元素的大小来走。

画面：同一数组中的一个元素宽度化为测距线，不将int大小说成语言固定。

动作：type_stride

```c
sizeof(int)
```

## s28 · array

数组下标和这条路也接上了。第二项，就是从第一项的地址走一步，再访问那里的内容，读到八。

画面：索引1与地址偏移路径合流到同一8；代码只留一个等式。

动作：index_equivalence

```c
scores[1] == *(scores + 1)
```

## s29 · safety

不过，有地址的样子，不代表就能访问。空指针没有指向有效对象，沿着它去读写，程序就可能出错。

画面：NULL指针悬停在边界闸门外，无造假的0地址可访问格。

动作：null_guard

```c
int *p = NULL;
```

## s30 · safety

还有一种更隐蔽：房间已经退租，手里却留着旧门牌。对象生命结束后，原来的指针就不能再拿来访问。

画面：函数局部对象退出作用域，虚线旧路径停在闸门，禁止实际解引用。

动作：lifetime

## s31 · safety

数组也有边界。最后一项后面的位置可以用来判断走完了，但那里没有下一项，不能当成分数读取。

画面：one-past端点画终点线，不画可读第四格，不执行越界。

动作：one_past

```c
int *end = scores + 3;
```

## s32 · safety

这些错误不保证立刻报错，也可能悄悄改坏别的数据。动手前确认三件事：目标有效，仍然活着，没有越界。

画面：三个检查嵌在同一内存走廊闸门上，保留大字，不制造错误运行数据。

动作：check_three

## s33 · recap

再看这块计分板：变量保存分数，指针保存地址，沿地址可以访问原来的分数，函数也就能帮它加一。

画面：镜头连续回到最初计分板，地址、内容、函数因果链同屏短暂可见。

动作：return_score

```c
int score = 7; addOne(&score);
```

## s34 · recap

下次看到星号和与号，先想这两个动作：拿到地址，沿地址找到东西。七变成八，背后的路就清楚了。

画面：完整路径闪过一次，计分板8定格，留出末尾来源时间。

动作：payoff

```c
&score  →  p  →  *p
```
