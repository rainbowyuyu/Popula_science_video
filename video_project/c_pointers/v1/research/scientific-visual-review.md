## 应修复

### P2：s25中的地址值与访问路径不同步

位置：World.ts `pointerValue` / `activeArray` / `target`。前两者使用 `action('s25',t,.42)` 默认1.2秒，目标插值使用2.6秒。实际帧06686中，p已显示0x2004，箭头仍在[0]的0x2000附近，字幕正在说“它会去第二名的位置”。初学者会把同一地址理解成指向两个不同对象。

建议：同一个moveToSecond进度驱动路径、地址值和高亮；地址在落定时换到0x2004，过渡中可简化为移动中的地址牌。s16同样存在value于句首变0x1040而目标延后2.8秒的潜在不一致，需用同一状态事件解决。已发送给visual代理。

### P2：s31代码声明end，模型仍显示p

位置：Film.tsx从story读 `int *end = scores + 3;`；World.ts把唯一指针格p的值改成0x200C。语义上这行代码创建的是end，既有p并不会因此被改写。

建议：s31–s32把该教学指针格名称改为end，或者把代码显示成 `p = scores + 3;`。首选前者以保持原剧本代码。不能让“一行声明end”被看成“自动修改p”。

### P2：s26应明确显示元素大小，不重复对已移动的p加一

位置：s25执行后，p指向scores[1]；s26代码仍显示 `p + 1`，路径仍停在scores[1]。作为泛指示意可解释，但连续程序状态容易让观众以为p+1仍指向第二项。

建议该句显示 `sizeof(int)`，配短标签“本次：4字节”；当前旁白已经明确“这次运行”及平台差异。无需改配音。s27仍讲类型决定跨度，s28再显示数组下标等式。

## 建议统一，但不影响核心结论

- s25再次显示 `int *p = scores;`，s29再次显示 `int *p = NULL;`。作为独立片段都成立；作为一条连续程序会重复声明p。为保持同一对象旅程，可改成赋值 `p = scores;`、`p = NULL;`。不必增加“示例独立”小字。
- 函数内的copy格当前标“地址副本”，与外部p自己的0x3000地址分开，不会误把p本身当成原score。建议保留这个明确区分。
- 指针格与整数格外形接近，不代表内存占用大小相同。当前只有数组每元素的四字节块被展开，没有把p错误标为4字节，合格。不要未来用相同宽度推出sizeof相同。
- s32门牌0x200C仍显示时，三条检查只是访问前条件；它当前仍是不可解引用端点，不能因为出现检查文字而把它改成可访问的绿灯。现有代码未出现第四项或读出数据，合格。
- 数组末端标记22.49、下标中心13.95/17/20.05以及标签23.1不严格按字节比例；它们是示意对象/边界排布，标签地址算术正确。建议保持端点为一条线，避免把它画成第四格。
