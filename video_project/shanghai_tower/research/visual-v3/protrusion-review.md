# 核心筒与桁架镜头“钢梁尖刺”定位

2026-10-09。实际查看 `tmp/stills/frame-2350.jpg` 与 `frame-3900.jpg`，并读取原始 GLB、模型 manifest、建模脚本及 World 的分类/透明/拆解逻辑。未修改模型或 World。

## 确定原因

主要对象是 `FACADE_RADIAL_TRUSSES_Z01` 至 `Z08`，manifest 角色为 `facadesupport`。建模脚本 `scripts/build_tower.py` 第 211–219 行在各区环带高程构建 24 组径向三角支承，每组两根水平工字梁和一根斜工字梁，从内层楼面边缘连到外幕墙。幕墙拆开后，它们自然比主体楼面更向外突出；它们没有变成异常无限长几何。

修复前 `World.ts` 存在分类遗漏：

- `shell` 只匹配 `ENVELOPE|SPIRAL_RIBS|GLAZING|FACADE_OUTER`，没有这些支承。
- `truss` 只匹配 `OUTRIGGER|BELT|CONNECTION_PLATES` 及 `outrigger/belt` 角色。
- 核心筒俯视的透明对象清单也没有 `facadesupport`。

因此外幕墙已平移 34 个 Three.js 世界单位离屏时，外幕墙支承留在原地、opacity 仍为 1。第 2350 帧 `corePlan=1`，普通楼面梁收到 `0.015` 的透明度乘数，这些支承却仍为 `1.0`，所以出现“多数梁透明，但一圈尖刺不透明”的强烈反差。第 3900 帧在伸臂特写中，楼面梁也按相应阶段弱化，外幕墙支承仍抢在前景。

## 直接定位证据

用实际 GLB、原相机轨迹、1920×1080 / 34° 视场，在人工选中的尖刺像素附近发射射线。射线检测只针对疑似幕墙支承网格，不是完整场景遮挡认证：

| 抽样帧与像素附近 | 命中的实际网格 |
|---|---|
| 2350，(765,80) | `FACADE_RADIAL_TRUSSES_Z03` |
| 2350，(1646,885) | `FACADE_RADIAL_TRUSSES_Z02` |
| 3900，(700,315)、(776,349)、(1822,414)、(1134,288) | `FACADE_RADIAL_TRUSSES_Z04` |

独立脚本为 `diagnose-protrusions.ts`，原始结果为 `protrusion-diagnostic.json`。

## 排除项

- **不是有限元位移炸开。** 两个抽样帧都为 `solverPlayback='none'`、权重 0。
- **不是非有限坐标或法线异常。** 8 组支承网格共检查每组 5,184 个导出顶点，坐标均有限；单位法线长度最大误差约 `4.2e-8`。
- **不是远移玻璃或支承的投影。** 导入时 `castShadow=!/ENVELOPE|FACADE|GLASS/.test(id)`，玻璃、立面与此类支承均不投射阴影。可见暗线可直接射线命中支承三角面。
- **不是模型尺寸异常增大。** 支承最大水平半径由底部约 53.13 m 逐区缩到顶部约 39.19 m，与其连接外幕墙的既有重建几何范围相符。这个检查只确认内部一致性，不把教学模型升级为施工图精度。

## 对 root 修复的复核

root 已将 `FACADE_RADIAL_TRUSSES` 同时加入 `shell` 与 `rib` 判断。当前逻辑下，这些支承与 `SPIRAL_RIBS` 一样在核心筒和受力特写中沿既有离屏方向整体平移；在幕墙介绍 `skin≈1` 时回到装配位置。

该修改覆盖了遗漏的移动分支、幕墙弱化分支和施工裁切顺序。此时无需再给核心筒透明清单追加它们：核心筒特写时它们已在镜头外，用户仍能看到它们经过镜头移动离开的过程。原型不需要重建，GLB 与求解数据均可保留。

需要最后实际重渲确认 2350/3900 的画面，并在幕墙介绍阶段确认支承回归后与内外幕墙连接自然。本文是原因定位与源码修复检查，不替代那次渲染验收。
