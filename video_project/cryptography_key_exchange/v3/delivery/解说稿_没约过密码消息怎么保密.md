# 没约过密码，消息怎么保密？

给妈妈订个生日蛋糕，你的地址会先被陌生人看见吗？你正坐在咖啡店，用店里的免费无线网下单。

“送到幸福路八号，别按门铃，我下来拿。”地址、电话、这点小心思，都得经过店里的路由器。

要是有人能截住路上的数据，你准备的惊喜，会不会先被一个陌生人看光了？

更奇怪的是，你和蛋糕店从没商量过密码，手机凭什么一上来，就能把话藏得严严实实？

先把这条网线想成一根透明管子。假如直接送原话，谁在中间截到它，谁就能读出你的地址。

所以，手机要先动个手脚：把能读懂的内容，变成看起来杂乱的一串数字，再送上网。

先看加密完成后的样子：蛋糕店收到这些数字，再还原成订单。两头都能读懂，路上经过的却是另一副模样。

让这件事成立的关键，叫密钥。它就是一长串秘密数字，可以把它理解成打开这份信息的钥匙。

在这个环节，手机和网站要拿到配套的秘密，才能一边加密、一边解密，外人没有就很难读懂。

麻烦就在这里：要是把钥匙也从管子里送过去，旁边的人照样能截走。那这把锁，岂不白上了？

密码学有个很巧的办法：双方先交换一些可以公开的东西，再各自在本地，算出共同的秘密。

这一步不好凭空想。咱们暂时把数字换成颜料，在手机和蛋糕店面前，各放一只小杯子。

先来一点大家都能看到的黄色。这是共同的起点，你知道，蛋糕店知道，旁边偷看的人也知道。

接着，手机偷偷挑一种红色，留在自己这里。这份私人材料，从头到尾，都不往管子里送。

蛋糕店也挑一种自己的蓝色，同样留好。双方可以各选各的，没必要提前约好挑哪一种。

现在，手机把黄色和红色混起来；蛋糕店把黄色和蓝色混起来。两杯颜料，变得不一样了。

把混好的这两杯交换过去。注意，网上跑的是混合后的结果，各自私藏的原色，还在原地。

所以，旁观的人能看到黄色，也能拿到这两杯混色；但双方自己还各握着一份没有交出去的材料。

手机拿到店家的混色，再加进自己留下的红色。这只杯子里，就有了黄色、蓝色和红色。

蛋糕店也做同样的事：在手机送来的混色里，加进自己的蓝色。里面也是黄色、红色和蓝色。

看，两边最后一样了。加入的先后不同，凑齐的材料相同，所以各自在家，也能得到共同结果。

这就是最妙的地方：共同的秘密，在两端分别做了出来。它没有作为一份完整答案，在网上跑一趟。

电脑当然不用颜料。真正用的是一类正着算容易、倒着推很难的数学运算；颜色只帮我们看懂步骤。

不过，还差一个小心眼：管子另一头，真的是蛋糕店吗？万一有人冒名接话，秘密就约错了人。

浏览器会查证书是谁签发的、网址对不对，再请对方证明：它确实握着对应的私人钥匙。

这像核验身份证，再让本人证明身份。只复印一张证书，没拿到那把私人钥匙，也过不了这一关。

这些检查和约定秘密的步骤，合起来叫握手。通常在订单内容发出去以前，浏览器已经替你做完了。

握手通过，刚才算出的秘密还会加工成加密用的密钥。接下来，订单就能沿这条连接安全地传过去。

还得防一种坏心眼：有人读不懂，却随手改动路上的数据。比如把密文中的一个数字，换了一下。

发送时还会带上一个需要密钥才能做出的核验标记。数据一改，标记就对不上，网站会拒收。

这里用真实程序试了一次：完整的数据能恢复订单，改动一处后，程序报错，没交出一份错误的地址。

现在再看那根透明管子：它能运送你的秘密，却不必知道秘密是什么。蛋糕店收到订单，开始准备惊喜。

这里保护的是手机到网站这一段。网站要读订单，才能给你做蛋糕；它怎么保存你的信息，还得另外负责。

两头约好秘密，手机认准网站，再检查有没有被改动。一会儿，蛋糕悄悄到了楼下。门铃没响，你准备的惊喜也还在。
