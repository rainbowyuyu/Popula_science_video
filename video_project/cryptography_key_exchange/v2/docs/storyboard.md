# 《让小偷送秘密》V2 前期故事与逐句动作建议

> 本文件为前期动作建议，部分细节在制作中调整；交付采用的七幕与接力关系见 `shot-contract-final.json`，实际采用资产见 `asset-provenance.json`。不把本表中的所有建议视为已实现功能。

冻结稿：`src/story.json`，32 句，1295 个纯汉字、1464 个含标点字符。七幕 `opening / secret / exchange / intruder / identity / delivery / ending`。目标约 300 秒，实际时长以用户 TTS 原速合成为准；不得为了贴合纸面时长强行加速。旧版咖啡馆、蛋糕、台座说明和固定双圆盘不继承。

## 故事因果与空间线索

一封信在不可信的路上旅行。开场红色改字是“如果被改”的威胁预演，尚未把原文明文交给信使；不能先让信使知道原文，再宣称加密使他忘掉了原文。相同信封、折痕和封口作为贯穿全片的视觉线索，观众可以认出它。

收发两端可用街道两侧的窗或门表示，路线真实贯穿空间，信使的身影占住中间岔口。摄像机贴着纸张、沿信件飞行、经过桥孔或门框完成接力。不要每幕摆一组物体等相机讲解，也不要把各物件依次摆进固定展台。

身份段 s17 明确从朋友送信类比转到“浏览器访问网站”的真实机制； s30 明确回到送信游戏。证书检查只画网站域名，不暗示网页证书验证现实朋友的私人身份。开锁、颜料、蜡封都只是机制隐喻；本版不做颜料类比，也不画成三把锁传来传去的另一种协议。

## 逐句动作建议

下面是画面应证明的动作与镜头接力，供视觉实现取舍；不是额外字幕清单。每个镜头至少在一句开始后和结束前留下可辨认的动作结果。

| ID | 画面动作与焦点 | 摄影与文字落点 |
|---|---|---|
| s01 | 近看纸上“今晚八点，老地方。”，纸折起向路口滑去，信使影子横过路线。 | 从纸纤维上方掠过，抬起看见长路。片名只出现一次，位置由纸与阴影留出的空处决定。 |
| s02 | 半透明威胁预演：八被划掉、九浮现，两只时针错开；随后预演沿原纸划痕退走，信仍在发送端。 | 镜头穿过时针空隙回到纸面，明确“如果被改”，不要表现为小偷已经获得原文。 |
| s03 | 街路拉成多个转交节点，信封从前景向远处传递，摄像机沿路线低空跟随。 | 屋檐与桥拱自然遮挡衔接，只保留一封信作为锚点。 |
| s04 | 封口合上，钥匙沿同一路出发；在信使位置出现复制动作，两把相同钥匙分别去向朋友和信使。 | 不新增信息卡；摄影机跟钥匙经过信使身边，侧面露出留在他手里的复制件。 |
| s05 | 朋友门外显出网站入口的轮廓，钥匙送进机房的远路不断延长。 | 一段短促、幽默的后退揭示“总不能先跑一趟”；随后沿门框转回发送端。 |
| s06 | 两端各有一个被罩住的私密输入；加工后的公开结果从窗口滑出，私密输入保持原地。 | 透过半开窗能看清谁留在本地、谁在路上；“私密 / 公开”只在必要的第一遍出现。 |
| s07 | 两份公开结果交换位置，分别进入对端；各与当地私密输入结合，两个相同的结果在各自窗内长出。 | 镜头从一端沿光路扫到另一端。共有结果绝不能被画成沿街寄送过去。 |
| s08 | 信纸展开成纸面计算路径，公开 5 和 23 在纸上；25 个小节跨过 23 格后留下 2。 | 从纸面飞行逐渐倾斜到俯视，只做一次余数说明。避免又建双圆盘讲两分钟。 |
| s09 | 左端私数6触发 `5⁶ mod23 → 8`，右端私数15触发 `5¹⁵ mod23 → 19`，公开8/19被信使带到对侧。 | 运镜沿交换路径，最终值在送出前停稳。6和15始终不离开自己的窗。 |
| s10 | 收到19的一侧执行 `19⁶ mod23 → 2`；收到8的一侧执行 `8¹⁵ mod23 → 2`。 | 同一横移中完成两次计算，各给最终2清晰的停留，不能旁白说结果2时仍停在中途余数。 |
| s11 | 两条指数路径在纸面并排伸长：`15×6` 与 `6×15` 汇为90，落到同一个2。 | 用轻微环绕展示同一结构；只在此时出现 `5⁹⁰ mod23 = 2`，不堆所有公式。 |
| s12 | 小数字6很快被试出来；纸面数字向远处展开成大规模结构，信使的追赶逐渐落后。 | “Diffie–Hellman”短标签可贴在路径起点。大规模示意不写未核对的破解年限。 |
| s13 | 摄影机跟着8，信使在桥洞扣住它、换成另一颜色；反向19也被换走。 | 主动调包必须在视野内发生。新的公开值使用颜色区分即可，不必再教一套算术。 |
| s14 | 一条路变成左右两段：你—信使持有一对青色钥匙，信使—对端持有一对蓝色钥匙。 | 从信使肩侧向两边扫开，两套钥匙颜色/形状匹配，不能只展示孤立两把钥匙。 |
| s15 | 同一信到中央打开，文字短暂可见，再被另一色钥匙保护后继续走。 | 跟信穿过信使所在的门框；开、读、重新封好三个动作要看得见。 |
| s16 | 镜头转到信使背后，他两侧的假名字翻转，露出同一人。 | 先揭穿角色，再把“中间人”短字靠近其阴影。不要切出另一个定义画面。 |
| s17 | 朋友收信窗口变成网站入口，门牌明确为示例域名 `meet.test`；证书里的同名与门牌对齐。 | 在同一门框内完成朋友→网站的类比过渡。身份公钥有独立颜色，不和会话钥匙混用。 |
| s18 | 沿证书的签发线向上穿过中间签发者，到浏览器预先信任的根；检查光沿原路径返回。 | 链条嵌在门框/墙面中，避免三个证书卡片静态排布。根是预先信任的起点，不靠自己签自己来赢得信任。 |
| s19 | 本次交换记录像长纸带展开，含公开8/19；网站用私钥产生随记录变化的数字签名。 | 从纸带上方滑过到签名位置；印章是动作隐喻，输出签名应体现绑定了这一份记录。 |
| s20 | 信使复制证书但改换握手数字；原签名与改后的记录核验失配，入口关闭。 | 错误发生在核验处，拒绝结果持续到坏记录离场，不能闪红后自动变绿。 |
| s21 | 网址和证书身份确认，旁边关于信誉的装饰问号留在门外。 | 一笔带过，不增加大段警告或独立信誉教程。此处只阐明证书能证明的范围。 |
| s22 | 两端共同秘密进入本地派生结构，长出本次连接的钥匙；身份钥匙留在原来的位置。 | 沿本地计算路径微距推进。短标“会话密钥”，口播用“这次连接的钥匙”。 |
| s23 | 同一纸信在发送端变成密文纹理，沿路转弯；到接收端才显回原文字句。 | 跟随飞行，靠纸折痕确认身份。原文不得在公共路段保持透明可读。 |
| s24 | 信使在密文表面改动一个小块，色差沿纸折痕向接收口移动。 | 与前句保持同尺度，追踪改动点。不要让改动被解释成有意把明文八点精准改成九点。 |
| s25 | 标签与密文一起进入核验口，密钥参与核对；坏信在入口停住，内容不交给应用。 | 微距横移同时看见数据和标签。认证标签与“证书/签名”使用不同形状，避免混同。 |
| s26 | 信使照抄标签，改动后的包仍验不过；缺少的秘密输入留在收信端内部。 | 以一个小动作展示“没有秘密就重做不了有效标签”，不再开新场景。 |
| s27 | 显示实际程序的原文和一小段真实密文字节；正常包经过核验后恢复“今晚八点，老地方。”。 | 字节从 `src/crypto-evidence.json` 读取，不能随机造数字。成功恢复要显示在接收端。 |
| s28 | 实验将首字节 `E6 → E7`，只翻一个比特；原标签留着，接收端给出验证失败，不输出文字。 | 错误包沿侧路退出，紧跟镜头可看见它确实被拒绝。首字节以实际证据文件为准。 |
| s29 | 信使把另一封外观相同的测试信扣在手里，路线未抵达；发送端等待/重发，清楚区分保护内容和保证送达。 | 从核验口拉到整条路，转场由信使挡住镜头完成；不要暗示加密能强迫攻击者转交。 |
| s30 | 回到纸信世界，正常的信穿过已经修复的路，进入朋友门内。 | 相机沿熟悉路线返回，三种检查保持背景线索，不再重讲三段教程。 |
| s31 | 路变回简洁的网络连接，两个端点发出同色脉冲，中间机器只转发密文。 | 用一次后退展示生活与机制关系。避免突然切到独立网页屏幕。 |
| s32 | 场景回到约定地点，钟到八点，两人如期碰面，信使的影子停在远处。 | 舒展的环绕收尾；末尾让引用在仍然移动的环境中进入，留足阅读时间。 |

## 审稿后保留的科学边界

- 公开8/19和私密6/15不能换位；共有2留在两端。`src/math-evidence.json`为实际计算结果。
- 小参数示例明确可穷举，不能把它包装成真实安全系统。现代网站常用椭圆曲线形式，片内不声称都直接用模23。
- DH交换本身不认证对端，主动调包需在建立秘密时发生；不能画成攻击者途中随便加入已认证连接就能解密。
- 身份私钥/签名、会话密钥/认证标签各有用途。数字签名不是固定印花贴纸，认证标签也不是任何人可重新计算的普通校验码。
- s27—s28是真实密码原语实验，不是完整 TLS 协议实现，也不声称执行了真实证书链验证。
- s29明确可用性边界；网络长度、时序等侧信息在本片范围外，不做“什么都看不见”的绝对宣传。

## 终稿读音

大部分口播使用“钥匙”。s12字幕保留“迪菲—赫尔曼密钥交换”，`spokenText`采用“迪菲赫尔曼交换的方法”，避免当前个人TTS对“钥”字读音不稳定；其他句文本相同。各个整数使用完整中文，没有“120”式数字串读法问题。字幕/标签术语仍可使用“身份公钥、身份私钥、会话密钥”，但应以观众已经看到的动作作为依据。
